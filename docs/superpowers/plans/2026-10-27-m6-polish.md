# M6 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in user refreshes the current listing, pins folders as favorites, searches a volume by file name, switches to a grid of thumbnails, finds what fills a disk with a space-usage screen (or the size of one folder), and gets a finished dark theme, read-only volume UX and phone layout.

**Architecture:** Favorites are a new SQLite-backed server domain. Search is a breadth-first, cancellable walk in `storage`, answered synchronously with a result cap. Thumbnails are a new server domain that decodes common images with the pure-Rust `image` crate, caches small JPEG/PNG files under `/config/cache/thumbnails` keyed by path, size and modification time, and serves them inline under a sandbox CSP. Space usage is a new background-task kind: a parallel, cancellable walk in `storage/usage.rs` (std threads, no new crate) that keeps a folder tree in the task's memory, browsed through a new endpoint. The web app gains a refresh button, a favorites section in the sidebar, a search field with an inline results view, a grid view sharing the list's menus and dialogs, and a space-usage page.

**Tech Stack:** Existing M5 stack. New server crates: `image` 0.25 with `default-features = false, features = ["jpeg", "png", "gif", "webp"]`; `sha2` moves from dev-dependency to dependency. Web: more `web-sys` features (`AbortController`, `AbortSignal`, and what the grid needs). No other new crate.

**Spec:** `docs/superpowers/specs/2026-10-18-explorer-design.md` (milestone 6 of §14; §7 top bar, sidebar, grid view, space usage, theme, mobile; §9 read-only volumes, thumbnails, search, favorites, space usage scans). Refresh and space usage were added to the spec on 2026-10-27 at the owner's request (same commit as this plan).

## Review Focus

1. **Typing fast in the search field on a big volume.** Each keystroke must not leave a full-volume walk running on the server: the web aborts the previous request, the server's walk notices the dropped request and stops. Test in Task 3 (`search_stops_when_cancelled`).
2. **A hostile or broken image.** A 30000×30000 PNG, a truncated JPEG, a `.jpg` that is really text: the thumbnail request answers 404 `thumbnail_unavailable` quickly, without exhausting memory, and the tile falls back to its icon. Tests in Task 4 (`thumbnail_refuses_oversized_image`, `thumbnail_of_corrupt_file`).
3. **Phone photos.** A JPEG with EXIF orientation 6 gets an upright thumbnail. Test in Task 4 (`thumbnail_applies_exif_orientation`).
4. **A tree with hard links, a symlink loop, an unreadable folder and a nested mount.** Space usage counts a hard-linked file once, never follows the symlink, marks the unreadable folder `incomplete` instead of failing, and does not enter another filesystem. Tests in Task 5 (`usage_counts_hard_links_once`, `usage_does_not_follow_symlinks`, `usage_marks_unreadable_folders`).
5. **A favorite whose folder was renamed or deleted, or whose volume is gone.** It shows as missing (not a link), can be removed, and causes no error toast. Test in Task 2 (`favorites_mark_missing_folders`).

### Task 5: Space usage scan (server)

Commit: `feat(server): space usage scans as background tasks`

**Files:**

**Interfaces:**
- Produces:
  ```rust
  // shared::api::tasks
  TaskSpec::Usage { source: Location } // serde op "usage"
  // shared::api::usage
  pub enum UsageKind { Dir, File, OtherFiles }
  pub struct UsageItem { pub name: String, pub kind: UsageKind, pub bytes: u64, pub files: u64, pub incomplete: bool }
  pub struct UsageView {
      pub volume: String, pub root: String, pub path: String, pub scanned_at_ms: i64,
      pub bytes: u64, pub files: u64, pub dirs: u64,
      pub incomplete: bool, // something under this folder could not be read
      pub collapsed: bool,  // folder limit reached: its sub-folders are counted here, not listed
      pub items: Vec<UsageItem>, // biggest first, at most USAGE_VIEW_LIMIT
  }
  // storage (usage.rs)
  pub const USAGE_THREADS: usize = 4;
  pub const USAGE_MAX_DIRS: usize = 1_000_000;
  pub const USAGE_TOP_FILES: usize = 20;
  pub const USAGE_VIEW_LIMIT: usize = 200;
  pub struct UsageTree { /* root RelPath, scanned_at SystemTime, nodes: Vec<UsageNode> (index 0 = root, a child always after its parent) */ }
  impl UsageTree {
      pub fn root(&self) -> &RelPath;
      pub fn totals(&self) -> (u64 bytes, u64 files, u64 dirs);
      /// `path` is volume-relative and must be the root or under it; None if it is not a scanned folder.
      pub fn view(&self, path: &RelPath) -> Option<UsageNodeView>; // storage-side twin of UsageView without volume/root strings
  }
  pub fn usage(volume: &Volume, path: &RelPath, progress: &(dyn TransferProgress + Sync)) -> Result<UsageTree, StorageError>;
  // server tasks
  impl Tasks { pub fn usage(&self, user: &str, id: &str) -> Option<Arc<UsageTree>>; } // done Usage tasks only
  ```
  - Rules (`du -x` style): each entry is measured with `rustix::fs::statat(dir, name, AtFlags::SYMLINK_NOFOLLOW)`; size = `st_blocks * 512`; folders count their own blocks too. A regular file with `st_nlink > 1` is counted once per `(st_dev, st_ino)` across the scan. Symlinks are measured as links and never followed. A sub-folder whose `st_dev` differs from the start folder's is not entered and not counted. The staging folder is skipped. A folder that cannot be opened or read is counted for what was read, gets `incomplete`, and calls `progress.skip()`; the scan goes on. Sub-folders are opened with no-follow semantics relative to their parent's handle (never by path string).
  - Parallelism: `std::thread::scope` with `USAGE_THREADS` workers sharing a queue of `(Dir, node index)` jobs (Mutex + Condvar + count of busy workers, so the workers stop when the queue is empty and nobody is busy). Each worker reads one folder at a time, adds its files to the node, keeps the node's `USAGE_TOP_FILES` biggest files by name and folds the others into an "other files" count and size, and pushes a job per sub-folder. Once `USAGE_MAX_DIRS` nodes exist, new sub-folders are still walked but counted into their parent node, which becomes `collapsed`. When all workers are done, totals are summed bottom-up by walking the node vector backwards. Workers check `progress.is_cancelled()` before each folder; a cancel returns `StorageError::Cancelled`. Progress: `add_file` + `add_bytes` per file.
  - `view`: the node's sub-folders and kept files, plus one `OtherFiles` item when files were folded, sorted by `bytes` descending, cut to `USAGE_VIEW_LIMIT` (the rest folded into the `OtherFiles` item).
  - `POST /api/tasks` with `Usage`: `Action::Read` on the source, which must be a folder (`not_a_directory`, `path_not_found`). The runner stores the tree in the task entry (a `OnceLock<Arc<UsageTree>>` next to `Progress`), so it lives and is pruned with the task (`FINISHED_TTL`). `files_total`/`bytes_total` stay `None`.
