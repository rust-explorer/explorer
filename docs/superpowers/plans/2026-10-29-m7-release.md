# M7 v1.0 Release Implementation Plan

**Goal:** Ship v1.0.0: the items left for this milestone by earlier reviews, complete docs, a release pipeline gated on CI, then the public repository and the tagged image `ghcr.io/rust-explorer/explorer:1.0.0`.

**Architecture:** No new user-facing feature except the language picker on the sign-in pages. Server additions stay in their domain (`auth`, `http`, `config`). The publication steps (repository visibility, tag) run only on the owner's explicit go, after they tested the image on their NAS.

**Spec:** `docs/superpowers/specs/2026-10-18-explorer-design.md` §12–§14 ("v1.0 release — docs complete, tagged image on GHCR").

## Global Constraints

- Everything from the M1–M6 plans' Global Constraints still applies (English, sparse comments, no commit rewriting, all filesystem access through `storage`, blocking calls in `spawn_blocking`, no `document::eval`, inline unit tests, domain folders, en/fr/es strings, files under ~400 lines of non-test code).
- **Branch** `m7/release` from `main`, one commit per task (`feat(auth): …`, `docs: …`); a fix after review is its own commit. One PR, merged with a merge commit.
- A behaviour, variable or limit visible to operators is written in `docs/` in the same commit.
- `cargo xtask ci` (with the Docker image) passes locally and on the Linux CI before merge.

## Tasks

### Task 1: Rust 1.98 (done, `5571386`)
Toolchain, `rust-version` and docs follow the base image bump of #88; clippy 1.98 fixes.

### Task 2: Private CA for the OIDC provider
- `EXPLORER_OIDC_CA_FILE` (optional): a PEM file whose certificates are trusted, in addition to the built-in roots, by the HTTP client used for discovery, JWKS and token calls (`auth/oidc/discovery.rs::http_client`).
- Unreadable file, or a file with no certificate → startup error naming the variable (same style as the other config errors).
- Tests: config parsing (unset, valid PEM, empty file, missing file); the client accepts a server whose certificate is signed by the given CA (a test TLS server with a generated CA, if the existing test setup allows it without a new dependency; otherwise a unit test on certificate loading).
- Docs: `docs/configuration.md` row; `docs/installation.md` line about private CAs (currently "not supported") and how to mount the file.

### Task 3: Rate limiting of anonymous sign-in endpoints
- `/auth/login` and `/auth/callback` are limited per client address: 20 requests per minute, burst 10. Over the limit → 429 `too_many_requests` with `Retry-After`, logged at warn with the request id.
- Client address: the TCP peer, or, when the peer is in `EXPLORER_TRUSTED_PROXIES` (comma-separated CIDRs, default empty), the rightmost `X-Forwarded-For` entry that is not itself a trusted proxy.
- The limiter's memory is bounded (at most 10 000 tracked addresses; idle entries dropped).
- No new dependency unless unavoidable (a small token bucket in `http/` is enough).
- Tests: per-address limit and reset; trusted vs untrusted peer with `X-Forwarded-For`; bound on tracked addresses; config parsing of the CIDR list.
- Docs: configuration row, security.md (what is limited and why), installation.md (set `EXPLORER_TRUSTED_PROXIES` to the proxy network, with the GoDoxy example), `error-too_many_requests` in en/fr/es and in `crates/web/tests/locales.rs`.

### Task 4: Language picker on the sign-in pages
- The pages shown before or instead of a session (home sign-in screen, sign-in error, access denied) offer the same language choice as the user menu, stored the same way (`explorer.locale`).
- Extract the picker from `components/layout/user_menu.rs` into a shared component; works at 375 px, `dark:` classes, keyboard accessible.

### Task 5: Server housekeeping
- The expired-session cleanup `JoinHandle` (`auth/session.rs::spawn_expired_cleanup`) is observed: if the task ends or panics, it is logged at error.
- A test that lists every `VAR_*` constant in `config.rs` and checks each one appears in `docs/configuration.md` and in `.env.example` (commented out when optional).

### Task 6: Release pipeline
- `release.yml` runs the CI job (same entry point `cargo xtask ci --no-docker`) before building and pushing the image; the image job `needs` it.
- CI installs `dx` and `cargo-audit` with checksums checked (as the Dockerfile does), or document why not.
- Turn off dx telemetry in the image build and in CI if dx 0.7.10 has an opt-out (check its source); otherwise note it in `docs/development.md`.
- Workspace version `1.0.0`.

### Task 7: Docs for v1.0
- README: drop "work in progress", short feature list, a screenshot (light theme, sample files with no personal data, stored under `docs/images/`), quick start pointing at `ghcr.io/rust-explorer/explorer:1.0.0`.
- `CHANGELOG.md` with a 1.0.0 entry (features by area, the migration note, known limits from PR #87).
- Check the GoDoxy label form against the current GoDoxy docs and fix `docker-compose.example.yml` / installation.md if needed.
- Read every doc once for stale statements (milestones, "before v1.0" notes) and fix them.

### Task 8: Publication (owner's go only)
1. Make the repository public; enable private vulnerability reporting.
2. Tag `v1.0.0` on `main`; the release workflow publishes the image; make the GHCR package public if it is not; pull it anonymously to check.
3. GitHub release with the changelog entry; close milestone M7.
